## 一、测试策略（第 11 页）

### Q1：你们有哪些层次的测试？分别测什么？

**答：**

| 层次 | 工具 / 位置 | 测什么 |
|------|-------------|--------|
| **单元测试** | 后端 **Jest**：`monthly-heatmap-intensity.spec.ts` | 热力图强度纯函数（0–4 映射） |
| **集成测试** | 后端 Jest e2e/smoke；前端 **Vitest** integration | 真实 HTTP + MongoDB（CRUD、heatmap 结构、400 参数） |
| **契约测试** | `anitrack-tester/contract-validator` | OpenAPI vs 运行时：路径、方法、状态码、响应结构 |

> **注意（与 PPT 对齐）：** 热力图强度单测在 **后端 Jest**，不是 Vitest；前端 Vitest 侧重 **API 代理/集成**（如 heatmap integration）。

**EN:** Unit tests (Jest) for heatmap mapping, integration tests against MongoDB, contract tests against swagger.json.

---

### Q2：契约测试具体怎么跑？失败说明什么？

**答：**

```bash
cd anitrack-tester/contract-validator
node run-contract-test.js
# 或 npm run contract
```

默认 **`BASE_URL=http://localhost:3001/api`**。用 **AJV + SwaggerParser** 校验 schema，并对 `paths` 里**每种声明的 HTTP 方法**发冒烟请求。失败通常表示：**实现与 swagger.json 不一致**（缺路径、字段、错误码）。`CONTRACT_PENDING_PATHS` 为空时为 **严格模式**。

**EN:** Run contract-validator against localhost:3001 — it compares live responses to swagger.json.

---

### Q3：集成测试会不会依赖外部 Jikan？CI 稳定吗？

**答：** 后端 **`app.smoke-spec.ts`** **mock `AnimeMetaService`**，无 `MONGODB_URI` 时可用 **mongodb-memory-server**，**不依赖 Jikan 在线**。HTTP 冒烟脚本 `api-test-suite/run-all.js` 测 CRUD 闭环。Bee/Jikan 429 在契约里可对 POST 记 **warning**。

**EN:** Smoke tests mock external meta fetch; Mongo can be in-memory — no live Jikan required.

---

### Q4：改 API 后怎么保证没破坏前端？

**答：** ① 先改 **`swagger.json`**；② 跑 **contract-validator**；③ 跑 **Jest smoke + Vitest integration**；④ 前端 TypeScript + `lib/api.ts` 类型与字段名保持一致。这体现 **API-first**：契约是单一真相源。

**EN:** Update swagger.json first, then contract and integration tests, then the UI client.

---

### Q5：有没有测状态机 409 和 COMPLETED 副作用？

**答：** 有。`api-test-suite/run-all.js` smoke 覆盖 **非法 PATCH → 409** 与 **`completedDates` 自动维护**；Nest e2e/smoke 也有 heatmap 参数校验（`start > end` → 400）。

**EN:** Yes — smoke tests cover invalid transitions (409) and completed-date side effects.

## 二、响应式 UI（第 12 页）

### Q6：响应式做了哪些具体适配？

**答：**

- **导航**：`< md` **汉堡菜单**，`md+` 横排链接 + **中/EN 语言切换**  
- **Dashboard**：统计卡片小屏 3 列紧凑；Watching 横向滚动；当季推荐 **2 列 → sm 4 列**  
- **Library**：工具栏小屏纵向堆叠；`AnimeCard` **`density="compact"`**  
- **Timetable**：**多列横向滚动**（列宽约 200px，±2 周），左右箭头，**今天列高亮**；非「仅顶部日期条 + 单日列表」旧版  
- **Profile 热力图**：**横向滚动** + sticky 月份列；桌面格子 **16×16px**；tooltip 防裁切；起始月 **`StartMonthPicker`**（i18n 年月）  
- **Dialog**：移动端 **近全屏可滚动**（`dialogUi.ts`，`z-50`）；删除需 **二次确认**

**EN:** Hamburger nav, scrollable timetable columns, horizontal heatmap, compact cards, mobile-friendly dialogs.

---

### Q7：用什么断点？为什么不用 Bootstrap？

**答：** **Tailwind 默认断点**（`sm` 640 / `md` 768 / `lg` 1024），**移动优先** utility class。课程考点里的 **Bootstrap** 指 Nest **`bootstrap()` 启动函数**，不是 CSS 框架 Bootstrap（仓库未使用）。

**EN:** Tailwind breakpoints, mobile-first — not the Bootstrap CSS framework.

---

### Q8：整站双语和响应式有什么关系？

**答：** **壳层文案**（按钮、导航）走 `I18nProvider` + `messages/zh|en.ts`；**番剧标题**走 API 多语言字段 + **`pickAnimeTitle`**。切换语言 **不改 API 枚举**（如 `WATCHING`），也 **不会 reshuffle 当季推荐**（queryKey 不含 locale）。答辩演示建议 UI 切 **English**，PPT 用英文标签。

**EN:** UI strings are translated in the frontend; anime titles come from API fields — locale doesn’t change business enums.

---

### Q9：真机测过吗？还是只缩小浏览器窗口？

**答：** 交付前 **`npm run build`** 前后端均通过；答辩可用 **Chrome DevTools 设备模式** 演示窄屏。真机（iOS Safari / Android Chrome）为 **可选加分**，非硬性要求。

**EN:** We verified builds and narrow-viewport layout; device toolbar is enough for the demo.

## 三、演示计划与现场演示（第 13–14 页）

### Q10：演示前要检查什么？

**答：**

1. 终端 1：`anitrack-backend` → **`npm run start:dev`**（**3001**）  
2. 终端 2：`anitrack` → **`npm run dev`**（**3000**）  
3. MongoDB **`.env` / `MONGODB_URI`** 可用  
4. 浏览器 UI 切 **English**；可选预跑 **`node api-test-suite/run-all.js`** 确认有数据  
5. Profile 热力图若空：可跑 **`heatmap-seeder.js`** 播种  

**EN:** Backend 3001, frontend 3000, MongoDB up, UI in English, optional seeder for heatmap data.

---

### Q11：演示步骤建议说什么、证明什么？

**答（与 PPT 对齐，可微调 Timetable 表述）：**

| 步骤 | 证明的课程点 |
|------|----------------|
| **Dashboard** — Watching + 当季推荐 | Mirror 读路径、统计 API、薄前端 |
| **Library** — 搜索 → 只 POST `malId` | Jikan 后端代理、Cache-Aside、双表返回 |

| **Profile** — 点月份看 Activity | **服务端聚合**，非前端 filter |
| **（可选）Timetable** — 多列日期 | 镜像数据 + 柏林时区 + 响应式 |
| **（可选）语言切换** | i18n 壳层 + 标题字段切换 |

**EN:** Demo proves API-first CRUD, server-side validation, aggregated stats, and mirror-backed schedule.

### Q12：演示时 429、Mongo 连不上、搜索很慢怎么办？

**答（预案话术）：**  
「仓库里有 **Swagger 和自动化测试**；现场网络或 Atlas 可能延迟。Mirror 路径不依赖即时 Jikan；搜索若 429 会提示 **`UPSTREAM_RATE_LIMIT`**，可改演示 **Library 已有条目** 或 **Dashboard 镜像推荐**。」  
可切 **`/api-docs` Try it out** 展示 **`GET /api/anime`** 作为后备。

**EN:** Fall back to Swagger Try it out or mirror-based pages if Mongo or Jikan is slow.

## 四、局限与展望（第 15 页）

### Q14：项目主要局限是什么？为什么可接受？

**答：**

| 局限 | 说明 | 课程角度 |
|------|------|----------|
| **无登录 / 单用户 `TEMP_USER_ID`** | 未做多用户 Auth | 课程未强制；schema 已预留 `userId` |
| **时间表部分 TBD** | 上游无可靠 `airTime` / 映射不全 | 数据源限制，非 UI bug |
| **Bangumi 映射非 100%** | 标题模糊匹配会失败 | 已 Mirror-first + 后台 `[i18n-map]` |
| **swagger 与 POST 运维端点** | 部分 Bee POST 可能 429 警告 | 运维向，不影响核心 CRUD 演示 |

**EN:** Single-user mode, incomplete upstream air times, and imperfect Bangumi matching — acceptable for course scope.

---

### Q15：如果要做下一步，优先级是什么？

**答（与 Blueprint §10.5 一致）：**  
**性价比高：** Auth + 真实 `userId`、Timetable 页脚解释 TBD/`bgmId=0`、URL 级 locale。  
**可搁置：** 追求 **零 TBD** 专项、并行纯 Jikan `/schedule` 全站第二视图、过早全自动 OpenAPI 生成。  
**不推荐过度承诺：** 个性化推荐算法（除非有明确数据方案）。

**EN:** Next: auth and multi-user; optional UX copy for TBD slots; deprioritize zero-TBD data perfection.

---

### Q16：和 MyAnimeList / AniList 等现成产品比，你们的价值是什么？

**答：** 课程目标是展示 **全栈工程能力**：NestJS **API-first**、**契约测试**、**后端聚合/状态机**、**第三方 API 镜像与缓存策略**、**可演示的 Analytics（热力图）** — 不是商业级追番站。价值在 **架构与可维护性**，而非功能数量。

**EN:** The value is demonstrating API-first architecture, testing, and backend logic — not competing with MAL as a product.

### Q20：教授问「Heatmap 和 GitHub 贡献图有何不同？」

**答：** 坐标系不同：我们是 **人生纸格（月）** — 纵轴 12 月、横轴年份；信号来自 **追番行为**（added/completed 按月），不是 commit。强度规则在后端可配置（当前 `addedCount+completedCount` 阈值）。

**EN:** Monthly life-calendar heatmap from watchlist activity, not GitHub’s daily commit grid.
